# Agent Note：模型设置通过子 slot 暴露可叠加的行字段

Status: implemented

[English](2026-08-16-model-settings-field-extension-slot.md) | 中文

## 问题

模型页面会保留 pi-ai 模型条目上的未知属性，但只渲染 id、显示名称、上下文窗口和输出上限。因此，拥有其他适配器支持属性的功能虽然已有持久化路径，却没有组合位置：它只能替换整个模型设置页、导入编辑器实现，或者修改内置表单。每种做法都会把独立能力与模型页面已经负责的提供方发现、凭据、校验和设置冲突处理耦合起来。

输入模态直接暴露了这个缺口。`llm-pi-ai` 接受按模型设置的 `input` 声明，并以文本作为保守回退值，但内置表单有意保持精简。独立分发的能力编辑器需要编辑现有草稿，而不接管提供方写入。

## 决策

模型设置页声明根作用域的 list slot：`settings.models.model.fields`。其渲染位置位于每个 pi-ai 模型行的高级折叠区内，排在两个内置容量字段之后。该 slot 采用叠加语义，因此各字段插件使用不同 id 后可以依顺序渲染，既不遮蔽内置表单，也不相互遮蔽。

owner share 包含完整行草稿、从零开始的行索引、编辑器禁用状态，以及 `update(patch)` 回调。该回调把键合并到指定行，并在 patch 值为 `undefined` 时移除对应键；现有模型列表更新仍是重建整行的唯一入口。模型页面继续通过现有 settings mutation 校验并持久化完整的 `models` 数组。

`ModelsSection` 持有 `renderSlot` 权限，并通过提供方编辑器和自定义提供方卡片向下委托收窄后的 `ModelFieldRenderer` 回调。后代组件不接收 registry 或 context 对象。该 slot 只在模型设置页条目注册期间存在，贡献方使用 `ctx.slots.inject`，因此激活顺序保持独立。

内置模型设置包不占用这个 slot。产品组合自行选择公开哪些附加模型属性，核心编辑器继续专注通用提供方字段。

## 备选方案

- **直接在内置编辑器加入 `input`** —— 这只解决一个属性，却会让提供方表单继续承接未来每一种需要展示的能力；它也会推翻精简表单的既有决定，而不是建立扩展点。
- **用更丰富的模型页面替换 `settings.section`** —— 这会重复提供方 join、凭据处理、发现、校验和具备冲突保护的持久化逻辑，而且替代页面会错过原页面之后获得的修复。
- **通过 DOM 观察注入控件** —— DOM observer 没有带类型的草稿或 patch 路径，并依赖私有标记，因此只能绕过页面写入设置，或者模拟用户交互。
- **把 slot registry 传给模型组件** —— 组件会获得超出此子 slot 的框架 context 和渲染权限，违背四类 props share 的 slot 模型。委托已获授权的渲染函数能让权限继续归属于 `ModelsSection`。

## 影响

外部浏览器插件只需一个小型展示组件即可编辑模型属性，并且不导入模型页面实现。持久化路径继续沿用未知字段保留、设置 revision 和校验行为。Harness 的共享改动只包含一个带类型的 slot 声明、一个渲染位置，以及穿过现有组件的普通回调委托。

该 slot 目前只出现在 pi-ai 模型行中，因为 `ModelListEditor` 的行是结构开放的，并且对应适配器 schema 拥有按模型能力。DeepSeek 专用 catalog 编辑器保留适配器定义的纯文本行为。

## 测试

模型设置 apply 测试校验子 slot 的运行时规格。提供方表单测试让一个贡献字段经过完整委托路径渲染，应用数组值 patch，并观察现有 settings mutation 把它持久化到指定模型行。生成的客户端 slot catalog 记录公开 owner share 与声明位置。
